# Discussion Prep

## Non-Technical Explanation

This repo is structured to show evidence, not just conclusions. Each training run produces a raw log. The scripts then extract tables from those logs. That means every number in the writeup can be traced back to the original MaxText output.

The work compares three things:

- Hardware: CPU vs GPU vs TPU
- Dense model scale: Qwen 0.6B vs a scaled ~1B Qwen
- Architecture: dense transformer vs mixture-of-experts transformer

Synthetic data is used because the assignment is about training mechanics and hardware behavior. It avoids confusing the comparison with dataset download or preprocessing issues.

## Technical Questions To Be Ready For

### Why synthetic data?

It isolates model and hardware behavior. Real data would introduce tokenizer, I/O, network, cache, and shuffle effects. Those are important in production, but they would make this assignment's hardware/model comparison noisier.

### Why does CPU differ from GPU and TPU?

Training is dominated by tensor operations, especially matrix multiplications. GPUs and TPUs are built for high-throughput parallel tensor math and bfloat16/float16 execution. CPUs have fewer vector/matrix units and lower effective throughput for this workload.

### Why does the scaled Qwen run slower than Qwen 0.6B?

The scaled model has wider hidden states, larger MLPs, more attention heads, and more layers. That increases parameters, activation memory, optimizer state, and FLOPs per step.

### Why not use MaxText's built-in Qwen 1.7B?

The assignment note asks to scale toward 1B. The built-in 1.7B config is a larger jump and may be less practical on free Colab hardware. The custom ~981M target is closer to the assignment's requested scale.

### What is active vs total parameter count in MoE?

Total parameters include all experts. Active parameters are the subset used for a token. With top-k routing, only `num_experts_per_tok` routed experts plus shared experts are active per token, so active compute can be much lower than total model size.

### Why might MoE not be faster in this assignment?

At small scale and batch size, routing, expert dispatch, and compiler overhead can offset the savings from sparse activation. MoE benefits are clearer at larger scale and with hardware/runtime settings optimized for expert parallelism.

### What makes the submission auditable?

- Config choices are in `configs/runs.json`.
- Every MaxText command is generated by `scripts/run_maxtext_colab.py`.
- Raw logs are preserved in `results/raw_logs/`.
- Derived tables are generated by `scripts/parse_maxtext_logs.py`.
- The final writeup points back to raw evidence.
